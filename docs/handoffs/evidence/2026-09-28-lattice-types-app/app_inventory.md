# The app's octet-only inventory (lattice types round 1, U3)

2026-10-01, PR #354's branch at 19a1443b, after merging main and #358 (core 19a1443bee65). Written BEFORE any code, as 03-app-spec §3 requires. Read-only sweep by four parallel readers and a completeness critic. Every row was read at its file:line.

**How to read it.** Each row gives:
- `what`: what the site does;
- `fix`: where its number must come from once a type is live, using the per-type facts in 02-core-spec §5; or "already from core"; or "keep" (octet by ruling M4/R9, or an app rule).

Most octet dependence carries no "octet" string. It comes through `LatticeType` used as a source: `LatticeType.named()` silently falls back to octet for any id it does not know.

**Status today.** No type is live in core. Generatable ∩ certifiable = ["octet"]. So no row changes behaviour until core publishes its BRIDGE CONTRACT; each row is fixed in the sync that lights its type.

**Octet byte moves.** A swap that would move octet bytes is not made; it goes to the maintainer (see "Octet byte hazards").
