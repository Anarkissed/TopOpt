## 1. Chips off the drag handles (shipping blocker)

The axial/margin/depth value chips rendered **on top of** the red clearance drag knobs, so the
knobs couldn't be grabbed. Two things caused the overlap:

* the chip was **centred** at `knobX + 46` via `.position`, so a wider number slid its LEFT edge
  back onto the ~50 pt knob hit target; and
* the chip carried the "MARGIN" caption + Auto/reset chrome, making it wide.

**Fix** (`WorkspacePlaceholder.clearanceValuePill`): anchor the chip's **leading edge** a fixed
clearance right of the knob centre instead of centring it. A right-extending, **hit-transparent**
container (empty `Spacer`, no background → touches fall through to the knobs/camera) pins the
number-only chip left, so its left edge lands at `knobX + chipKnobClearance` regardless of the
value's width.

* `chipKnobClearance = 40 pt`. The knob's grab circle is `size/2 + 12 ≈ 25 pt` when active
  (`clearanceHandleKnob`, `.contentShape(Circle().inset(by: -12))`); 40 clears it with ~15 pt of
  air. The knobs still draw from the **uncollapsed** `clearanceHandleItems`, so every wall/cap/face
  stays grabbable.

Evidence: `assets/round6_1_chips_off_handles.png` (before: pill sitting over the dashed hit-halo;
after: knob fully exposed, narrow `1.5 mm` chip beside it).

## 2. Number-only chips + external labels (HARD RULE: never two rows high)

`GlassValuePill` gained two flags: **`showTitle`** (the internal "MARGIN"/"AXIAL"/"DEPTH" caption)
and **`showChrome`** (the trailing Auto badge / ↺ reset). Both default `true` (unchanged for any
other caller).

* **3D viewport** (`clearanceHandleChip`): `showTitle: false, showChrome: false` → a bare
  scrubbable number, exactly like the load-weight chip. The handle glyph (↔ margin, ↕ axial,
  ⊤ depth) names the value, so the caption is redundant and its removal is what makes the chip
  narrow enough to clear the knob (item 1). **Reset-to-Auto moved to the panel** (see below) — the
  one deliberate functional move; the viewport number still scrubs/taps-to-type and stays tinted
  while it reads Auto.
* **Selections panel** (`clearancePrimitiveLine`): the caption is now **text OUTSIDE** the chip
  ("Margin:" / "Axial:" / "Depth:") beside a number-only pill (`showTitle: false`, chrome kept), and
  **each metric is on its own row**. The old layout packed a captioned Margin pill + a captioned
  Axial pill into one `HStack` which, right-aligned under the trash icon in a 300 pt panel, wrapped
  mid-word into a two-row smoosh. One metric per row cannot wrap — the HARD RULE holds.
  `sharedClearanceChips` (synced groups) stacks the representative bore + plane vertically for the
  same reason.

Evidence: `assets/round6_2_panel_no_wrap.png` (before: "MA/RGI/N", "1/./5", "mm" wrapping; after:
`Margin: [1.5 mm ↺]` / `Axial: [3 mm ↺]` on clean rows).

## 3. Gizmo rotation arrows were mirrored

The curved roll arrows rotated the view **opposite** to the way they point. Root cause: in
`OrbitCamera`'s y-down screen space a **positive `roll` rotates the image clockwise** (the
`up`/`orbit` comments), so the CCW-glyph left arrow (⟲) sending `+rollStep` spun the view CW, and
the CW-glyph right arrow (⟳) sending `−rollStep` spun it CCW.

**Fix** (`OrientationGizmoView.controls`): flip the two signs — left ⟲ → `−rollStep` (CCW image),
right ⟳ → `+rollStep` (CW image). The glyphs and the ⟲/⟳ toast labels are unchanged; only the sign
of the roll each sends. Camera math (`OrbitCamera.rollBy`) is untouched, so the existing
`OrientationGizmoTests` roll assertions still hold.

Evidence: `assets/round6_3_gizmo_rotation.png` (marker rotated by the value the left arrow sends —
before CW/mirrored, after CCW/matches).

## 4. Undo / redo

**Buttons:** two round buttons to the RIGHT of the name/material header
(`WorkspacePlaceholder.chrome` → `undoRedoButton`), styled like the back chevron; they enable/dim
with `project.canUndoNow` / `canRedoNow`.

**Gestures** (iOS, in `MetalMeshView`): two-finger **double-tap = undo**, two-finger
**triple-tap = redo**. Both need two touches (no collision with the one-finger pick tap); the
double `require(toFail:)` the triple so a genuine triple redoes. New `onUndo`/`onRedo` closures are
threaded through `MeshViewInputs` → the coordinator's `handleUndoTap`/`handleRedoTap`. **iPad
only** — a Mac trackpad two-finger tap is not a `UITapGestureRecognizer` event, so the header
buttons are the macOS affordance.

**Mechanism** (snapshot-based, `UndoHistory.swift` + `ProjectModel`):

* The undoable slice is `EditSnapshot { selection, force, designBox }` — the three Equatable/Codable
  value structs a workspace edit mutates. A snapshot is a cheap by-value copy; equality is exact.
* `UndoHistory` is a **pure** bounded stack (seed / coalesce / undo / redo / branch / depth) —
  headless-unit-tested. `baseline` = the last committed state (== live at rest); `commit` records a
  step only when the slice truly differs; `undo`/`redo` move the baseline between two stacks and
  return the slice to apply.
* `ProjectModel` drives it with a **debounced auto-commit**: `objectWillChange` → `.debounce(400ms,
  RunLoop.main)` → `commitUndoSnapshot()`. A drag/scrub/painted-stroke burst coalesces into ONE
  step; an unrelated republish (camera tick, `quality` toggle, run progress) is a guarded no-op that
  never manufactures a phantom step or loops. `performUndo` commits any in-flight edit first, so the
  header/gesture always start from the state on screen. `seedUndoBaseline()` runs after init AND
  after a `restoring` init, so the undo **floor is the loaded/restored project**, never "before
  load".

### Stack depth & scope (as required)

* **Depth:** 50 steps (`UndoHistory(depth: 50)`); the oldest step drops off the bottom past that.
* **Granularity:** one step per **settled interaction** (coalesced within a 400 ms quiet window) —
  not per keystroke/drag-frame. Two distinct edits done inside 400 ms collapse into one step.
* **Undoable** (anything that mutates the slice, captured by value — so no per-action wiring):
  * selection edits — tap-to-select / deselect, loop picks, **painted strokes** (see coordination);
  * group changes — add / remove / rename / recolour / set-active, anchor/load role, direction,
    weight, keep-clear + protect affixes;
  * clearance / margin / axial / depth edits (handle drags **and** chip scrub/type), sync toggles;
  * design-box + keep-out edits (enable/disable/reset/resize/move).
* **NOT undoable** (outside the slice, by design): project **name** & **material** (header rename /
  material menu), **quality**/resolution, print params, camera pose (orbit/zoom/pan/roll/gizmo
  snap), and the optimize **run** itself + its results.

### Paint-task coordination

The paint task (`claude/mesh-selection-paint-mode-8bd279`) lands painted strokes as
`SelectionModel` selection edits. Because the undo slice is captured **by value** off
`selection`, a settled painted stroke is folded into one undo step **automatically** — no
paint-specific hook is required. The one contract for the paint task: let a stroke **settle**
(stop mutating `selection`) between strokes you want as separate undo steps; strokes finished
within the same 400 ms window coalesce into one, same as any other edit.
