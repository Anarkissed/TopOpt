# ACTIVE DOMAIN — production arming

## THE DECISION (recorded verbatim, not re-litigated)

> The maintainer has decided to arm Active Domain in production.

This handoff IMPLEMENTS that decision. It does not re-open it. Everything below
is the arming (the one-line production flip, its named constant, its tripwire, its
parity assertions, its run_info echo) and the before/after evidence the decision
is now accountable to — the same shape as the recycling arming (handoff 133 /
PR 163), which recorded its own maintainer ruling verbatim in §10 and then shipped
the armed package against it.

**Status:** Armed, core only. `configure_production_options` now sets
`opts.simp.active_domain_band = -1` (AUTO). The LIBRARY default stays `0` (OFF), so
Gate-V2, the property suite and every core reference run — none of which call that
function — are BYTE-FOR-BYTE unchanged (THE ONE RULE). The production diff is
**+101 lines, 0 deletions** (`evidence/.../production_diff_stat.txt`): purely
additive, the `band == 0` path untouched.

**One caveat this arming carries that recycling did not:** the band is NOT
bit-identical when on. It is an approximation — the eliminated elements carry a
real `rho_min^p ~ 1e-9` stiffness, so the restricted trajectory answers a slightly
different question (the FINAL certified compliance solve is always full-domain, so
the certificate is never restricted). Arming it therefore changes the PRODUCT
slightly, and that is exactly why it waited on the escape latch
(2026-07-25-ad-escape-latch): the growth invariant that makes the mask sound is
EMPIRICAL, not a theorem (168 measured 6 979 escapes on a stagnating trajectory).
The latch detects the first live escape at O(N) cost and reverts to the full
domain for the rest of the run.

### A5 — RECYCLING INTERACTION, verified not assumed

Recycling (armed, Jacobi-only, k = 16) keeps a fixed-dimension basis keyed to the
free-DOF count `n`. AD changes `n` as the band moves. Two questions, both answered
with the mechanism AND the measurement:

**1. Is the recycle space reset correctly when the DOF set changes? YES, by
construction.** `RecycleSession::begin(n, …)` drops the carried basis whenever
`g_space.n != n` (`recycle.cpp:283`), and `commit()` stores `g_space.n = n`
(`recycle.cpp:588`). A dropped-basis solve becomes a bootstrap: it charges ZERO
setup matvecs and applies NO correction (it only harvests, which is free), so a
DOF-set change degrades recycling to a clean, exact no-op — never a stale basis
applied to the wrong-sized operator, never wasted cost. Exactness is unconditional
regardless (any SPD basis keeps the preconditioner SPD), so even a same-`n`,
different-mask collision costs iterations at worst, never correctness.
`test_recycle`'s lifetime assertion already pins "a DOF-count change drops the
basis rather than misapplying it".

**2. Does recycle_dim collapse with AD armed? Measured, in the regime where
recycling can wrap at all.** Recycling is Jacobi-only, so it wraps NOTHING on the
healthy gate fixture (0/98 solves ran Jacobi — the armed gate confirms
`rc_frac` N/A there, a clean no-op). The interaction is only observable in the
STAGNATION regime, where multigrid falls to Jacobi-CG:

Stagnation fixture (73 728 elements, 48.8× dilution), single rung, 20 iterations,
recycling armed in BOTH postures (`evidence/.../stag.log`):

| posture | Jacobi solves | recycled (rc_frac) | setup matvecs | escape latch |
|---|---|---|---|---|
| OFF (band 0) | 3/20 | 2/3 = **0.667** | 28 | — |
| ARMED (AUTO, k=4) | 3/20 | 2/3 = **0.667** | 31 | @iter 3, 1378 escapes |

**`rc_frac` is IDENTICAL (0.667) with AD armed. recycle_dim does NOT collapse.**
The mechanism is the escape latch, not luck: on this divergent trajectory the latch
fires at iteration 3, and the solves that fall to Jacobi (where recycling can wrap
at all) are the expensive EARLY ones at iterations ≥3 — by which point AD has
already latched off and they run on the FULL domain, so the recycle basis never
sees an AD-churned DOF count on a solve it wraps. Iterations 1–2, while AD was
still restricting, were multigrid-carried (recycling is a no-op there). So the two
features' active windows do not overlap on a single solve, and the measurement
confirms it: recycling keeps its full Jacobi-regime behaviour with AD armed.

**A5 verdict:** the two features COEXIST safely — reset is correct (code + measured),
exactness holds, a dropped basis costs nothing, and `rc_frac` is unchanged (0.667
armed vs 0.667 off). The escape latch actively PREVENTS a sustained collision by
turning AD off before it can churn the DOF set on a Jacobi solve. This is NOT a
blocked-stop: neither feature degrades the other.

## THE HONEST GAP — state it, do not let the table imply otherwise

**168's 1.79× was measured on a FIXTURE (24 576 elements, healthy multigrid). It
has NOT been measured on the maintainer's real stagnating 128³ design-box job**,
where the multigrid hierarchy builds, fails to contract, and the run falls to
roughly 20 000 Jacobi iterations per solve. AD shrinks the domain, so on that job
class it SHOULD cut Jacobi work substantially and may beat 1.79× — **but that is a
PREDICTION, not a measurement.** The arming table above must not be read as
transferring the fixture number to that job.

What CAN be measured here is a STAGNATION FIXTURE (73 728 elements, 48.8× dilution,
the 49×-class size 168 §1a showed reproducing the 125 stagnation). It is reported
as its OWN row, NOT as the 128³ job, single rung, 20 iterations
(`evidence/.../stag.log`):

| | OFF (band 0) | ARMED (AUTO, k=4) |
|---|---|---|
| Jacobi-fallback solves | 3 / 20 | 3 / 20 |
| escape latch | — | **fires @iter 3, 1378 escapes** |
| f_bar | 1.000 | 0.969 (latched off @3) |
| CG iterations | 36 034 | **34 670 (0.962×, 3.8% fewer)** |
| mean\|Δρ\| @20 | — | 3.15e-3 |
| max\|Δρ\| @20 | — | 7.56e-2 |

**Read this row honestly, three ways:**

1. **The escape latch fires at iteration 3 (1378 escapes)** — this fixture's
   trajectory IS divergent (168 measured 6 979 escapes on such), and the latch
   caught it, reverting to the full domain. So AD ran restricted for only 2
   iterations before turning itself off. The `3.15e-3` mean|Δρ| is exactly the
   pre-detection drift the escape-latch handoff already charged as its B5 (`3.2e-3`
   on its own stagnation fixture) — the damage from the 2 restricted steps, stopped
   at iteration 3 instead of compounding over 20.
2. **The win here is small (0.962× CG) and comes from those 2 restricted steps, not
   from a sustained restriction** — because the latch turned AD off. On a DIVERGENT
   stagnation trajectory, arming AD buys little: the latch (correctly) prevents it
   from running restricted.
3. **This fixture is NOT the deep-Jacobi regime the real 128³ job is in.** Its
   multigrid mostly RECOVERS (only 3/20 solves fall to Jacobi — the early
   iterations, the 125 pattern), whereas the maintainer's job falls to ~20 000
   Jacobi iterations per solve SUSTAINED (multigrid never recovers). So even this
   "stagnation" row understates the depth of that job — and it cannot tell us
   whether that job's trajectory is DIVERGENT (the latch fires, AD turns off, ~1×)
   or merely SLOW-BUT-CONVERGING (the latch stays quiet, AD runs restricted the
   whole way and could beat 1.79× by cutting a 20 000-iteration Jacobi solve to the
   active set). **That distinction is the entire size of the win, and it is
   unmeasured.**

The real 128³ job at production scale was not run (a single full ladder there is
~11 h of wall clock — 168 §1a). **That measurement is owed before the fixture win
is quoted as production truth.**
