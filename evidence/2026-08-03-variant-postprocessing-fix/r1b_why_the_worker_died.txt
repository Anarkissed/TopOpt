   A deliberate stop() sets shouldRun=false and never restarts => UNEXPECTED exit.

4. No crash report for the worker or for Python. The only report anywhere near the
   window is a CORE TEST binary (test_loadcase_analyze, 17:00:38) — a different

   (reports whose name matches python/topopt_worker/TopOpt Worker: 0)

5. The reason it exited: UNRECOVERABLE.
   WorkerSupervisor.start() drained the worker's stdout+stderr into
     outPipe.fileHandleForReading.readabilityHandler = { h in _ = h.availableData }
   and the exit code lived only in a @Published UI string that start() overwrote
   with .running 2 seconds later. Fixed: see defect 6 in the handoff.
