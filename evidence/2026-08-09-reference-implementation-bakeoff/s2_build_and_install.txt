==============================================================
Task 2026-08-09-reference-implementation-bakeoff, S2(a): "APPLE SILICON IS A REAL
RISK AND IT IS THE FIRST THING TO SETTLE... IF IT CANNOT BE BUILT AND RUN ON HIS
HARDWARE IN A DAY, SAY SO AND STOP."

★ IT BUILDS AND RUNS, IN UNDER FOUR MINUTES, WITH NOTHING TO WORK AROUND.
The documented risk did not materialise.

Host: Apple M2 Pro (10 cores), 16 GB, macOS 15.5 (Darwin 25.5.0), arm64.

----------------------
  julia 1.12.6            /opt/homebrew/bin/julia, native arm64
  a ~1.5 GB ~/.julia depot from earlier work (Makie etc.); NO Gridap, NO PETSc,

  ★ NOTE FOR THE ADOPTION COST: Julia itself was NOT installed by this task, so

  `brew install julia` (a ~200 MB download).

THE SMOKE TEST, WHICH IS THE ACTUAL ANSWER
-------------------------------------------
  LOAD_GridapTopOpt_s = 6.7        (first `using`, precompiled)
  LOAD_Gridap_s       = 0.0
  LOAD_GridapPETSc_s  = 0.0

  MPI.MPI_LIBRARY = MPICH
    MPICH Version:   5.0.1
    MPICH configure: --build=x86_64-linux-musl --host=aarch64-apple-darwin20
                     --with-device=ch4:ofi:tcp
    -> a NATIVE aarch64-apple-darwin build, cross-compiled by the JLL system.

  GridapPETSc.with(args=split("-ksp_type cg -pc_type jacobi")) do ... end
    PETSC_INIT = OK

  ★ JuliaParallel/PETSc.jl issue 184 — the documented M-series difficulty the
  brief flags — is about building PETSc.jl against a hand-built PETSc. It does
  not apply here: GridapPETSc consumes `PETSc_jll`, whose arm64 macOS artifact
  is prebuilt and downloaded. Nothing on this machine compiled PETSc.
