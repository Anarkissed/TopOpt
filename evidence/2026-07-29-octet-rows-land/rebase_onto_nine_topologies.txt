REPRESENTATION — pointer + size (main's `RowTable`), NOT a fixed-size array
--------------------------------------------------------------------------
The structural conflict was already solved by #246. Before #246, rows_of returned
`const std::array<Row, N>&`, which hard-codes ONE row count for every topology — the
exact thing that breaks when octet is 19 and the others are 8. #246 replaced that with

    struct RowTable { const Row* data; int n; bool empty() const {...} };
    RowTable rows_of(LatticeTopology topo);   // returns {table.data(), table.size()}

a view (pointer + length) returned by value. resolved_span / lattice_rho_min/max /
lattice_cubic_tensor all consume RowTable, so they are size-agnostic. Chosen
representation: KEEP RowTable. Octet becomes std::array<Row,19>; rows_of already does
`{kOctet.data(), (int)kOctet.size()}` so it reports 19 with no change. The eight other
tables stay std::array<Row,8>; the three tetragonal return {nullptr,0}. Nothing in
rows_of / the accessors needed editing for the size change.

(std::span was the other option but the codebase is C++17 and compiles without
-std=c++20; RowTable is the existing, already-proven idiom, so there was no reason to
introduce a new vocabulary type.)
