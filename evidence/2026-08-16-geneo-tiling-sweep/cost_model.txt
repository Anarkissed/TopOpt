==============================================================================
MODEL A — THE SHIPPED SKI-RENTAL GATE
==============================================================================
★ THE BASELINE IS HIS RUN AS IT ACTUALLY RAN — 438,348 CG over 160
stagnating design-iteration solves — and NOT a differently-tuned GenEO.
Comparing an accelerator only against other tunings of itself hides the
possibility that none of them earns its keep. See his_solves()'s
docstring for what that baseline is and is not: GenEO WAS active in it,
so it is not a clean GenEO-free control, and the direction of that
impurity understates every GenEO win reported below.

A solve whose plain cost is C pays:
    C                                if C <= threshold  (finishes plain)
    threshold + 2*N_t + 2*tail_warm  if C >  threshold  (engages)

    threshold = 2*N_t + 500 + 2*427
    all-in    = threshold + 2*N_t + 2*tail_warm

★ NOTE WHAT THE SECOND LINE MEANS, BECAUSE IT IS THE WHOLE STORY. The
burn is NOT refunded when the deflation engages — the solve has already
spent it. So all-in ALWAYS exceeds the threshold, and any solve whose
plain cost sits between threshold and all-in is one the gate engages
and LOSES on. That is the ski-rental 2-competitive bound showing up as
real iterations, and it is why the 'engage' and 'of which LOSE' columns
are printed side by side. An earlier version of this script modelled the
cost as min(C, all-in), which quietly refunds the burn; it made core=12
look like -0.6 % when it is really +13.1 %. The wrong version is named
here because it is an easy and flattering mistake to repeat.

★ READ THE SHIPPED ROW FIRST, BECAUSE IT VALIDATES THE MODEL. At
N_t = 1686 the model engages 8 of 160 solves and every one of them is a
LOSS. His run armed 12 and declined 156 — same picture, and PR 329's
finding in one line: the gate is doing correct arithmetic on a
mechanism that cannot pay at this basis size.

★ AND THE NON-MONOTONE MIDDLE IS THE REAL WARNING. Shrinking N_t from
1686 to 718 makes things WORSE, not better (+6.5 % -> +13.1 %), because
it drops the threshold into the middle of his solve-cost distribution
and the gate starts engaging on solves that were about to finish plain.
A tiling that halves N_t but lands there is a REGRESSION. GenEO only
starts beating no-GenEO-at-all at N_t of roughly 430.

★ AND THE CEILING THIS MODEL EXPOSES. Even at N_t = 100 the shipped
gate returns about -32 %. THE 21.7x IS NOT REACHABLE THROUGH THIS GATE
AT ANY BASIS SIZE, because the gate makes every solve burn its
threshold plain BEFORE deflating and never refunds it. The 21.7x
(5,412 -> 249, fea.hpp) is what deflation does running from iteration 0,
which the ski-rental policy forbids by construction.

==============================================================================
MODEL B — STANDING ARMING (deflate from iteration 0, no burn)
==============================================================================
    per solve = 2*N_t (refresh) + 2*N_defl

This is NOT a proposal and is NOT armed by this task. It is here
because it is where the 21.7x actually lives, and because the standing
posture was measured as a 1.25x LOSS (2026-08-02-geneo-standing-probe)
AT N_t ~ 1,686 — a verdict whose entire cost basis is the refresh term
this sweep moves. If a tiling shrinks N_t enough, that NO-GO is built on
a number that no longer holds and deserves re-asking. Separately.

★ READ THE 'n' COLUMN BEFORE COMPARING TWO MEASURED ROWS. The tail is a
median over n solves, and the tail GROWS with rung difficulty at every
tiling (core=8: 217/241/905 across rungs 1/2/3). So a row whose n is 1
is a median over whichever single rung happened to engage — for core=16
that is rung 3, the HARDEST — and it is therefore charged a worst-case
tail while rows with n=3 or 4 are charged a middling one. core=16's row
is PENALISED by this, not flattered, and its true standing-armed cost is
better than shown. Fixing it needs the forced-engagement probe at 16,
which did not run.
